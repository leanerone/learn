先正名

你脑子里的乱线团，其实只有 三层

你不是不会用 AI，而是没分清"对话里的 AI"和"能干活的 AI"。 本节我们一次性把脑子里混乱的词理清楚。

① 对话型

ChatGPT 网页、DeepSeek 网页、Qwen 网页 —— 你打字，它回字，本质是"问答机器人"。

② 工具型

VS Code + Copilot、Codex CLI、Cursor —— AI 直接进入编辑器，读写你电脑上的文件，是"程序员助手"。

③ 智能体型

Trae、DeepSeek Harness、智能体工作台 —— AI 能自己规划步骤、调用工具、执行多步任务，是"数字员工"。

三个最容易混淆的概念

词一句话定义谁提供能力类比
MCP (Model Context Protocol)让 AI 能"打电话给外部工具"的通信协议Anthropic 主导，多家支持USB 接口 —— 统一插头规格
Skill把"某种工作流"打包好的能力包各家平台 / 社区App —— 安装就能用
Agent能自己规划、调用 Skill/MCP 完成任务的程序AI 模型 + 工作台员工 —— 会自己用 App 办事

👉 记忆口诀：MCP 是插头，Skill 是 App，Agent 是会用 App 的人。

DeepSeek Harness 入门 · 安装 / 插件 / 自造插件 / 工作台

DeepSeek Harness(简称 DSH)是 DeepSeek 推出的 IDE 形态 AI 工具。下面我们一步步把"插件"和"工作台"讲明白。

4.1 安装 DeepSeek Harness

  1. 访问 deepseek.com 或官方 IDE 下载页，下载对应系统版本(Windows/macOS/Linux)。
  2. 安装过程和 VS Code 类似：下一步 → 勾选"添加到 PATH" → 完成。
  3. 首次打开使用 DeepSeek 账号登录；若无账号，手机号注册即可。
  4. 在 设置 → 模型 里挑 DeepSeek-V3 / R1，按需切换"快"(V3)与"深"(R1)。

4.2 安装插件(3 个必装)

① Chinese Lint

中文提交信息、注释规范。半导体项目多人合作用得上。

② SECS/HSMS Snippets

(社区版) 机台通信常用代码片段。装后输入 secs 自动补全。

③ MCP Bridge

DSH 原生支持 MCP，这里是"可视化配置 MCP" 的桥接插件。

操作路径：左侧插件图标 → 搜索 → Install → Reload，和 VS Code 几乎一样。

4.3 如何"创造"自己的插件(Workbench Skill)

DSH 的"插件"分两种含义，请区分：

类型本质难度适合谁
UI 扩展插件改界面/快捷键/侧边栏⭐⭐前端开发者
Skill(技能包)一段提示词 + 工具调用流程⭐所有 EAP 工程师

推荐做法：先学 Skill，不要碰 UI 插件。Skill 本质是一个 SKILL.md + 几个配置文件。

Step 1：建一个 Skill 目录

my-eap-skills/
└── secs-log-analyzer/
    ├── SKILL.md        # 告诉 AI"你是谁、能干什么"
    ├── tools.json      # 列出本 Skill 能用的工具(MCP)
    └── examples/
        └── sample.log  # 示例文件

Step 2：写 SKILL.md(给 AI 看的"说明书")

---
name: secs-log-analyzer
description: 解析 SECS-II / HSMS 日志，统计 Alarm 频次并分类
trigger: 当用户说"分析机台日志"、"alarm 归类"时触发
---

# 你的角色
你是一名 EAP 工程师助手，专门分析 SECS-II 日志。

# 工作流程
1. 用 `read_file` 读取用户给定的日志路径
2. 解析每一行，提取 Event / SxFy / AlarmID
3. 按 AlarmID 出现频次倒序，输出表格
4. 若频次 ≥ 3，标注为"高频"并给出建议

# 输出格式
Markdown 表格 + 一句话结论。

Step 3：在 DSH 中加载

DSH → 设置 → Skills → 添加本地路径 → 选择 my-eap-skills/ → 完成

之后只要在 DSH 对话框里说"分析机台日志"，AI 就会自动按你的 Skill 流程干活。

4.4 打造你的个人工作台

  • 把常用 Skill 集中放到一个目录，例如 D:/eap-skills/
  • 为不同项目建不同 Workspace(机台 / RCMS / AutomationUI 各一个)
  • 每个 Workspace 挂载相关 Skill，避免混乱
  • 模型策略：日常用 V3(快)、排查难题切 R1(深)、写代码可接 Copilot
  • 用 .dshignore 排除厂内机密文件，防止误上传

Codex 入门 · 网页 / 桌面 / CLI 三形态

OpenAI 的 Codex 现在不只是一个聊天框，而是一个真正能干活的代码 Agent。

5.1 三种使用形态

① ChatGPT 网页里的 Codex

挂在 ChatGPT 左侧，可读你 GitHub 仓库。开 PR、改 bug、跑测试。

② Codex Desktop

独立桌面应用，类似 Cursor。能接管你整个本地工程。

③ Codex CLI

命令行工具，npm i -g @openai/codex，终端里直接对话。最强大、最受开发者喜欢。

5.2 Codex CLI 安装(推荐你装)

  1. 需要 Node.js 18+(node -v 验证)。
  2. 执行 npm install -g @openai/codex
  3. 运行 codex，用 ChatGPT 账号完成登录(OAuth 弹窗)。
  4. 在项目根目录运行 codex 进入 REPL，直接用自然语言下指令。

5.3 Codex 的"超能力"：Skills & MCP

// ~/.codex/config.toml
[mcp_servers.filesystem]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "D:/eap-projects"]

[mcp_servers.github]
url = "https://api.github.com/mcp/"
headers = { Authorization = "Bearer xxx" }

上面这段配置说明：
• Codex 通过 MCP 加载了两个外部工具：本地文件 & GitHub。
• 装好后，Codex 的 Agent 就能"读你的 D 盘项目" + "操作 GitHub"。

VS Code + GitHub Copilot：你们厂的工作台主力

你们已购买 GitHub Copilot 企业版，这就是日常主力。本节讲清 Copilot 的全部能力、合规用法，以及如何给它"接上 MCP"扩展工具调用。

✅ 你们已经在使用 Copilot 的优势

• 企业版默认不上传代码片段训练(数据保护承诺)
• 管理员可以统一管控可见模型、审计日志
• 走公司账号 SSO，账号安全有保障
• Copilot 已原生支持 Agent 模式 + MCP，能力不输 Cursor

6.1 Copilot 全家桶（你可能不知道的 6 个能力）

① 内联补全 Tab

打码时自动灰色提示，按 Tab 接收。最常用、最快。

② Copilot Chat Ctrl+I

侧边栏对话。选中代码 → 问"这做了什么 / 怎么改 / 写测试"。

③ Copilot Edit Ctrl+Shift+I

多文件批量编辑模式。说"把所有机台脚本的命名规范改了"，它会**给出 diff 让你确认**。

④ Copilot Agent 模式（新）

AI 自动规划步骤：读文件→改文件→跑测试→循环迭代。你们的 EAP 任务用它最强。

⑤ Copilot Workspace

把整个 GitHub Issue 当成任务，AI 自动开 PR。跨模块重构、bug 修复 用这个。

⑥ Copilot for CLI / PR / Docs

终端对话、自动写 PR 描述、从代码生成 Wiki。装对应插件即可。

6.2 Agent 模式：Copilot 最强的功能（重点）

Agent 模式 = Copilot 不仅答问题，还能自己执行。操作路径：

VS Code 右侧 Copilot 图标 → 下拉选 "Agent" → 输入任务
示例输入:
  "帮我扫描 src/ 下所有 .java 文件，把 log.error 改成 slf4j 的标准格式，
   并自动跑 mvn test 看是否通过。"

Agent 会自动：

  1. 列出所有目标文件
  2. 逐个读懂上下文
  3. 给出修改 diff，等你点击 Apply
  4. 执行命令（编译、测试、git commit）
  5. 出错时自动调整重试

💡 EAP 工程师的 Agent 模式典型任务

• "把这个 Java 接口的所有参数校验补全"
• "给这个 RCMS 模块加 JaCoCo 单元测试覆盖率"
• "把 SECS-II 消息常量从硬编码提取到配置文件"
• "给 AutomationUI 的 Vue 组件写 props 类型定义"

6.3 Copilot + MCP：让它能"动手干活"

默认 Copilot 只能读 VS Code 里打开的文件。装了 MCP Server，它就能调用外部工具。配置方法：

// VS Code → 设置 → "MCP" → 添加 MCP Server
// 或者在项目根目录的 .vscode/mcp.json 中：
{
  "servers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y","@modelcontextprotocol/server-filesystem","D:/eap-projects"]
    },
    "github": {
      "command": "npx",
      "args": ["-y","@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "你的企业 PAT" }
    }
  }
}

配好后 Copilot 多了"工具栏"：能直接读 D 盘全项目、能直接开 GitHub PR。

6.4 合规使用 Copilot 的 5 条军规（厂内必读）

  • ❌ 不要把含客户代码 / 工艺参数 / 账号密码 / .env 的整段贴进 Chat
  • ✅ 选中代码块再问 AI（Copilot 默认只传你选中的部分）
  • 敏感模块先用 gitignore 或 Copilot 的 "Exclude files" 设置排除
  • AI 给出的代码必须人工 Review再提交，特别是 SECS 通信、状态机部分
  • 开启管理员审计日志（IT 已默认开启），不要试图绕过

⚠️ Copilot 与 Copilot 企业版的区别

你们买的企业版（Enterprise）承诺：
• 提示词与代码补全不会用于训练任何模型
• 数据隔离在企业租户
• 管理员可一键关停 / 删除历史
如果是个人版（Pro），请尽快升级到 Enterprise，否则合规有风险。
