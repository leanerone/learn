PART 04 · 核心概念

什么是 Agent

类比 fab:自动化机台 = Agent,人工补全 = 补全

🤖 补全(以前)

  • 你写一句,AI 接一句
  • AI 不能自己跑
  • AI 不能自己报告
→

⚡ Agent(现在)

  • 你给任务,AI 自己读文件
  • AI 自己改代码
  • AI 自己跑测试 + 报告

Agent 的循环:读任务 → 读文件 → 改 → 跑 → 报告。
你只负责点头 ✅ 或 ❌。

PART 04 · 核心概念

什么是子 Agent

大任务拆成小任务,并行跑

👨‍🍳
1 个 Agent
1 个厨师做 5 道菜
30 分钟
👨‍🍳👨‍🍳👨‍🍳
子 Agent(并行)
3 个厨师各做 2 道
12 分钟

fab 例子:让 AI 改 1 个需求,Agent 自动拆成
"改 drv"、"写测试"、"改文档"、"跑测试" 4 个子任务并行跑。

PART 04 · 核心概念

什么是 Skill

类比 fab:SOP 作业指导书 = Skill

💬 普通提示词

  • 每次都要重复说
  • "按我们厂的命名规范来"
  • "SECS 消息要有超时重试"
  • 换同事又得再说一遍
→

📋 Skill

  • 写一次,永久生效
  • 把规则写进文件
  • AI 加载后永远按它干活
  • 团队共享,大家都用

Skill = 写给 AI 的 SOP 文档。
我厂 EAP 至少需要 5 个 Skill,后面会讲。

PART 04 · 核心概念

什么是 MCP

类比 fab:SECS/GEM 通讯协议 = MCP

🗣 没有 MCP

  • 你:复制日志 → 贴给 AI → AI 分析
  • AI 只能"嘴上说"
  • 不能动你的电脑
→

🔌 有 MCP

  • 你:"分析最近 24h 的报错"
  • AI 自己读文件
  • AI 真的能动你电脑

MCP = 让 AI 真的能动手的协议。
没有 MCP,AI 永远只能"出主意"。

PART 04 · 核心概念

什么是团队循环(Team Loop)

类比 fab:机台 + RPA + MES 联动 = 团队循环

👤
单 Agent
1 个 AI 自己跑完整套
👥
多 Agent 协同
1 个写代码 + 1 个测试 + 1 个报告
🔁
团队循环
写 → 测 → 报告 → 改,自动循环

现在 fab 用不上,但 1-2 年后会有。
你要知道这个方向,但不必现在懂。

PART 04 · 核心概念

静态(Static)与子静态

从一次性提示词 → 模板化提示词

📌 静态(Static)

  • 写 1 次,用 1 次
  • 类比 fab:临时卡关指令
  • 例:"今天帮我看下这段代码"
→

📐 子静态

  • 把静态当"模板",嵌套复用
  • 类比 fab:通用卡关脚本
  • 例:"按 [命名规范] 审查 [代码]"

演进路径:静态 → 子静态 → Skill → Agent → 团队循环
