PART 04

几个 概念
听起来玄,其实简单

Agent、Skill、MCP,这些词网上很多,我用 fab 的话给你翻译

Agent

就是 帮你干活的人

Agent = 一个能 自己想办法 完成任务的助手,
你只需要说"做什么",不用教"怎么做"。
例子 1

查 alarm

你说"查一下昨天 ETCH-01 的 alarm",Agent 自己去连 log、解析、汇总

例子 2

写报告

你说"生成这周 SPC 异常报告",Agent 去取数、画图、写结论

例子 3

改 drv

你说"把 S1F1 的 timeout 改成 5 秒",Agent 定位代码、修改、测试

Sub-Agent

大 Agent 手下的 小组长

复杂任务拆给多个 Sub-Agent 并行做,
最后由主 Agent 汇总,像 项目经理带团队。
主 Agent

接收任务

"分析 ETCH 区三个月 alarm"

→
Sub A

拉 log

连 ECS 取数据

→
Sub B

解析

提取 alarm code

→
Sub C

汇总

生成趋势图

Skill

把 经验 变成 模板

Skill = 你教 AI 的 固定套路,
下次遇到同类问题,一键调用,不用重复教。
我的 Skill 1

SECS log 分析

输入:log 文件路径 + 时间范围 → 输出:alarm 统计 + 异常时间点 + 可能原因

我的 Skill 2

drv 测试文档

输入:drv 版本号 + 测试项 → 输出:标准测试报告模板,含 SECS 消息流

MCP

AI 的 USB 接口

MCP = 让 AI 能 连接外部工具 的标准协议,
就像 USB 让电脑能连各种外设。
MCP 1

文件系统

AI 直接读你电脑上的 log、文档,不用复制粘贴

MCP 2

数据库

AI 直接查 MES 数据库,取 SPC 数据

MCP 3

API

AI 调用 fab 内部 API,比如 RCMS 查询

Team Loop

AI 的 PDCA

Plan → Do → Check → Act,
AI 也能 自我迭代,一次比一次做得好。
PLAN

定计划

分析任务,拆解步骤

→
DO

执行

调用工具,跑流程

→
CHECK

验证

检查结果是否符合预期

→
ACT

优化

记录经验,下次改进

Static / Sub-static

AI 的 记忆 和 笔记

Static

长期记忆

跨会话记住的东西:你的代码风格、fab 的命名规范、常用的 SECS 消息格式

类似:老师傅的经验
Sub-static

临时笔记

单次会话记住的东西:今天查的 alarm、正在改的 drv 版本、刚读的 spec 章节

类似:便签纸

用好 Static,AI 会越来越懂你;用好 Sub-static,单次任务不会丢上下文
