AI 是什么
大词扫盲

市场上那么多词,先摊开,一个一个讲清楚

先听懂这些词

你可能听过,但 分不清

词一句话解释fab 类比

LLM · 大语言模型

AI 的 大脑,
但只是一个大脑

LLM = 一个 读过互联网上所有文字 的大脑,
你给它一段话,它预测下一句最可能是什么。
它能做

理解 + 生成

读你的话、懂你的意思、写出像人话的回复

它学过

互联网所有公开文字

书、文档、代码、论坛、论文,几千亿字

它怎么工作

预测下一个词

不是真的"理解",是统计学上最可能的延续

LLM 的边界

LLM 不能 干什么

不能 1

不能动手

你说"帮我查 ETCH-01 昨天的 alarm",它只能说"你应该去 ECS 查",不能真的去点鼠标

不能 2

不能查实时数据

它不知道现在是几点、机台现在的状态、你电脑上有什么文件

不能 3

不能连你的工具

它不能直接打开 VS Code、不能直接连 MES 数据库、不能直接发邮件

不能 4

不能记你一辈子

每次对话结束,它就忘了你是谁、你上次问过什么(除非有特殊机制)

这就是为什么要 Agent —— 给 LLM 装上"手"和"脚"

记住这条线:后面的每一个词,都是为了补前一个词的短板

第一层 · Agent

给 LLM 装上 手 和 脚

Agent = LLM + 工具 + 自主决策,
你说"做什么",它自己想"怎么做"。
fab 类比

像一个有经验的作业员

你只说"跑这批货",他自己知道选 recipe、上料、按 start,不用你一步步教

它能调用

工具 (Tools)

读文件、跑脚本、查数据库、发请求 —— 这些"手"都是外挂给它的

关键点

自主决策

遇到异常会自己判断:重试、换方案、或者停下来问你

第二层 · Sub-Agent

活太多,分包 给小弟

主 Agent 当 项目经理,
把大任务拆给多个 Sub-Agent 并行干,最后汇总。
主 Agent

接单

"分析 ETCH 区三个月 alarm"

→
Sub A

拉 log

连 ECS 取数据

→
Sub B

解析

提取 alarm code

→
Sub C

汇总

生成趋势图

fab 类比:就像跨区 issue,你拉蚀刻、薄膜、黄光三个人分头查,最后你汇总结论

第三层 · Skill

把 经验 写成 SOP

Skill = 你教 AI 的 固定套路,
同类问题下次一键调用,不用重复教。
fab 类比

就是一份 SOP / 作业指导书

新人照 SOP 就能上手,Skill 就是写给 AI 看的 SOP —— 输入什么、走哪几步、输出什么格式

我的例子

drv 测试文档 Skill

输入:drv 版本号 + 测试项 → 输出:标准测试报告,含 SECS 消息流,已复用 20+ 次

判断标准:一件事你重复做了 3 次以上,就值得写成 Skill

第四层 · MCP

AI 世界的 SECS/GEM

MCP = AI 连接外部世界的 标准协议,
就像 SECS/GEM 让任何 host 都能连任何机台。
没有 MCP 之前

各家各写各的接口

每个 AI 工具想读文件、查数据库,都要单独开发,互不通用

有了 MCP 之后

一次开发,到处能用

MCP Server 写好,任何支持 MCP 的 AI 都能直接连

对 fab 的意义

AI 可以直连 MES / RCMS

不用再复制粘贴 log,AI 通过 MCP 直接读数据

补充概念 · Team Loop

AI 的 PDCA 循环

Agent 干活不是一把过,
而是 Plan → Do → Check → Act,错了自己纠。
PLAN

定计划

分析任务,拆解步骤

→
DO

执行

调用工具,跑流程

→
CHECK

验证

结果对不对?编译过吗?

→
ACT

修正

不对就改,再来一轮

这就是为什么 Agent 写代码会自己跑测试、看报错、再改 —— 它在循环,不是一次性输出

补充概念 · 记忆机制

AI 的 长期记忆 和 临时笔记

Static · 长期记忆

跨会话都记得

你的代码风格、fab 命名规范、常用 SECS 消息格式 —— 写成规则文件,每次对话自动带上

类比:老师傅的肌肉记忆
Sub-static · 会话内记忆

只记这一次

今天查的 alarm、正在改的 drv 版本、刚读的 spec 章节 —— 对话结束就清空

类比:便利贴,用完就撕

实操:把"fab 通用规则"写进 Static(如 Copilot 的 rules 文件),AI 会越来越懂你

四个概念都是 给 LLM 补短板:补动手、补并行、补经验、补连接

最常被问的问题

DSH 上练好的东西,
能搬到 Copilot 用吗?

不能迁移

模型本身的"记忆"

你在 DSH 聊出来的上下文、它对你口味的适应,都锁在 DSH 里,模型权重你拿不走

就像你在 A 厂培训的产线经验,不会自动装进 B 厂的机台
可以迁移

你沉淀下来的"文本资产"

Prompt 模板、Skill 文档、规则文件(rules)、SOP 流程 —— 都是纯文本,复制过去就能用

Skill 写在 md 文件里,Copilot / DSH / Codex 都认

结论:模型不通用,但"你教 AI 的方法"通用。把经验写成文本文件,而不是留在某个工具的聊天记录里

公司还有两座平台

Dify / N8N:不写代码 也能攒 AI 流程

Dify 是什么

拖拽式 AI 应用工厂

拖几个框就能攒出一个"AI 问答机器人":接知识库、接大模型、发布成网页。适合给全组做一个"EAP 知识问答助手"

类比:fab 里的标准 recipe 模板,改改参数就能跑
N8N 是什么

拖拽式自动化流水线

把"收邮件 → 解析附件 → 调 AI 总结 → 发到群里"这种跨系统流程,用节点连起来定时跑。适合做"每日 alarm 自动日报"

类比:fab 里的自动搬送线,把站点一个个串起来

分工:Copilot/DSH/Codex 是"我个人"的工具,Dify/N8N 是"全组共用"的流水线 —— 个人的 Skill 跑顺了,就可以搬到 Dify/N8N 上让所有人用
